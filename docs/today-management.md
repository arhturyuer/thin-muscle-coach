# 今日页饮食与运动管理

周日历下方按饮食、运动两个模块展示。汇总由 `miniprogram/services/today-summary.js` 按所选日期计算，不持久化热量或进度派生值。

## 统计口径

- 摄入：当天当前餐次引用的 `mealAnalysis.analysis.consumed.energyKcal`，按分析 ID 去重；不统计孤立分析或被替换、撤销的引用。三餐实际记录优先，未记录使用建议，加餐参与统计。
- 文字与照片混合追加时，兼容性可选字段 `nutritionIncomplete` 标记未量化的餐食；`previousNutritionIncomplete` 随撤销交换。旧记录仍可读取，无需迁移。缺失分析或营养数值同样显示待确认。
- 日常活动：沿用 `guidance.walking`，根据目标步数与已同步步数分别计算目标和已消耗，不含基础代谢。步数缺失与真实零步数区别处理。
- 训练：使用绑定版本的当日运动方案热量，按各动作活动秒数分配整数热量（最大余数法，合计与当日目标相等），以实际活动秒数比例估算已消耗。组次完成状态独立于热量是否达标。
- 总剩余为活动剩余加训练剩余，每项剩余最低为零；超额活动不能抵扣训练。总进度按两项各自封顶后的完成量计算。
- 当日手动运动记录优先于旧计时训练记录；版本不匹配显示待确认。未来显示尚未开始，恢复日训练目标为零。

## 兼容接口

运动方案生成支持可选 `exercises[].targetMuscles` 数组，最多四项、每项最多十二字。旧方案使用明确动作名称映射；未知名称显示查看动作说明，不重新生成旧方案。

运动记录页接受可选 `moveId=move-N`，加载后滚动并突出对应动作；缺省或无效参数维持原入口。实际记录仍沿用原有组数、每组次数和活动秒数表单、权限校验及离线同步流程。

## 本地验证

`npm test`、`npm run check`；共享模块及云函数副本通过 `npm run prepare:cloud` 同步。新增测试覆盖摄入缺失、追加替换撤销、历史日期、热量分配、部分及超额运动、未知步数、恢复日、未来日期、记录入口和训练部位校验。

发布需同时考虑云函数新增训练部位字段与小程序展示；本次仅更新本地代码，未发布云函数或小程序。

2026-11-05 本地验收：310 项自动化测试通过，原生 WXML/WXSS 编译通过；模拟器已检查饮食空记录、恢复日、长动作名、计时动作、部分完成与动作定位。离线样例中保存一组计时动作后，训练已消耗由 23 更新为 46 千卡；验证后恢复原本的本地状态，并核验内存和持久化存储均已移除样例。

恢复日仅展示休息安排，不再提供运动记录入口；已有历史恢复记录继续保留。日常活动的同步按钮采用 Lucide refresh-cw 图标，紧随同步时间，仅在已授权的当天显示；未授权时显示开启权限入口，首次请求走原生授权、拒绝后走设置页，平台声明缺失时只展示原有诊断说明。
