## 数据及规则

评测 schemaVersion=3 新增 targetWeight、pace（gentle/moderate/fast）、stepGoal。保留版本2的读取与原计划；旧草稿进入第5步补充目标。计划协议仍为版本2，规则版本为 guidance-2；新能量目标版本为 energy-1。

共享计算入口位于 shared/guidance.js：energyTargets、dailyEnergy、energyPolicy。服务端保存 plan.energyTargets，nutrition.energy 与 intakeKcal 完全一致。每周估算体重变化，重新估算基础代谢及允许的能量差，最多推演520周；超过范围显示分阶段复评，不展示确定日期。7700千卡/千克仅作产品层能量换算近似，不作为长期临床预测。

| 参数 | 当前实现，待专业复核 |
| --- | --- |
| 基础代谢 | Mifflin–St Jeor，使用当前体重 |
| 活动基线 | 久坐1.2、轻度1.375、活跃1.55；对应4000、6000、8000步 |
| 步行估算 | 步长=身高×0.415，速度4km/h，MET=3；以 MET−1 计算净活动消耗 |
| 训练估算 | 当前居家非步行力量动作，MET=3.5，有效运动时间暂取可用时长60%，其余为休息与准备 |
| 维持消耗 | 基础代谢×活动系数＋相对基线步数差的净消耗＋一周计划训练净消耗/7 |
| 减重速度 | 每周当前体重0.25%/0.5%/0.75%，缺口不超过维持消耗20% |
| 增重速度 | 每周当前体重0.1%/0.2%/0.3%，盈余不超过维持消耗10%且不超过300千卡 |
| 饮食下限 | 现有审核规则仅有基础代谢下限，无另行批准的按性别固定下限；本次保留该下限 |
| 目标体重 | BMI 18.5–30（不含30）；差值≤0.1kg按维持 |
| 目标步数 | 整数1000–20000步；近期7个完整日期至少3天才显示平均参考，不自动修改用户目标 |

测试分区数值展示由独立 numericTargetsEnabled 控制，默认开放，可用 TEST_NUMERIC_TARGETS_READY=false 关闭；支付联调不再阻止数值展示。正式分区仍沿用 NUTRITION_READY/NUTRITION_REVIEW_ID。nutrition.numericEnabled 表示允许展示估算，nutrition.reviewed 保留真实审核状态，不以测试开放伪造审核完成。bootstrap 会为已有适用计划补齐当天目标快照，保留历史、训练进度和实际饮食记录；食谱使用保存的目标，不另行重算。

三档在预览中展示预计周期、每日摄入和周均活动消耗。今日活动按训练日/恢复日拆分；饮食始终按周均消耗保持稳定。缩短或暂停训练仅调整当日训练消耗，不减少饮食或增加步数。目标设置通过 plan.targets.update 从保存当天生效，以 targetHistory 保留各日期的目标快照。当前周的动作、训练进度和实际饮食记录保持不变；如同时修改训练条件，训练安排仍从下一周生效。今日目标版本更新后，旧食谱缓存失效，按新目标生成，不重写历史食谱。

## 接口与数据隔离

- plan.targets.update：assessment（版本3）、baseVersion、baseTargetsVersion、requestId；返回 state，返回 effectiveFrom 并立即更新当前计划的评测、营养与能量目标，保留 entitlement ID、version、训练日程及历史目标快照；训练条件变更单独排入 nextAdjustment。targetsVersion 单独控制目标设置并发，最近20个请求保留幂等回执。
- activity.steps.sync：cloudID、consent=true；调用者由云函数 OPENID 识别，服务端通过 cloud.getOpenData({list:[cloudID]}) 获取数据，校验返回 cloudID、appid、水印与数值。不接收明文步数作为可信数据。
- 步数存于现有账号集合 activitySteps，按上海日期覆盖；环境继续沿用 test/prod 集合隔离。仅保存最近30天及今天，来源、观测时间、同步时间和服务端序列。使用观测时间与序列抵御乱序；删除纪元阻止删除期间的请求重新写入。
- publicState 增加 activitySteps 与 dataEpoch。客户端同步与 bootstrap 合并时保留较新数据；跨账号、环境或删除后不导入在途结果。
- 食谱保存 targetVersion；客户端与服务端缓存均要求目标版本匹配。模型仅接收保存的摄入目标及必要评测，不发送 stepGoal、activitySteps 或能量计算中的步数依据。

## 微信运动上线核验

1. 按平台要求在小程序后台隐私保护指引声明微信运动步数用途，并核对接口可用资格。发布隐私页不代表后台声明已更新。
2. 部署测试业务云函数并在真实微信客户端点击“连接微信运动”，核验系统授权、APPID、水印与今日步数、历史日期。若平台阻止接口，保留不可用提示，不以模拟值代替。
3. 验证拒绝、撤销权限、关闭再进入、离线再联网、手动刷新及0步。授权后仅在打开小程序期间同步，自动请求至少间隔5分钟，无关闭后后台同步任务。
4. 在窄屏手机检查目标卡片、三档速度、步数输入与大字体布局；分别核验训练日、恢复日、缩短和暂停训练。
5. 删除个人数据后核验云端步数、目标及客户端缓存已清除；跨账号、测试/正式环境不共享数据。
6. 继续使用现有发布流程；本次不更改支付、销售或营养审核配置。

## 微信运动授权恢复修复（2026-11-04）

已对照微信官方接口类型声明和 CloudBase 开放数据说明：getWeRunData 以回调读取，读取前完成 wx.login；scope.werun 为运动权限；微信可提供今天及前30天数据；CloudID 需要在有效期内传入云端。客户端不上传 encryptedData、iv 或登录 code，不保存开放数据凭据。

本次发现并修复的确定性问题是：权限已被拒绝时，原按钮重复 authorize，没有 native openSetting 恢复入口；部分错误也被粗略归为未授权。现在明确区分首次申请与已拒绝，已拒绝显示原生 openSetting 按钮，用户开启后自动重新登录、取数、同步。后台自动同步不会打开权限设置。登录、隐私授权、取数和云端失败分别提示，诊断仅存阶段与安全错误编号。接口没有返回今天的数据时保留“未同步”，不当作0步或成功取数。

本次只修改小程序客户端，云端读取与校验保持不变，无需重新部署云函数。模拟器当前账号权限为 not_requested，不能据此判断手机端是否授权；手机实际授权与步数仍需用户验证。

参考：[微信官方 API 声明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)、[CloudBase 开放数据说明](https://docs.cloudbase.net/practices/get-wechat-open-data)。

## 微信运动真实故障根因与后台声明（2026-11-04）

原生调用已复现：wx.login 成功后，wx.authorize({scope:'scope.werun'}) 返回 `authorize:fail api scope is not declared in the privacy agreement`，wx.getSetting 的 scope.werun 仍为未申请。根因是公众平台隐私指引未声明微信运动步数，不能按用户拒绝授权处理，openSetting 无法补充开发者的接口声明。

由小程序管理员操作微信公众平台「用户隐私保护指引」：

- 新增收集项目：微信运动步数（后台通常显示为「收集你的微信运动步数」）。
- 使用目的填写：`同步每日步数，展示步数记录与目标完成情况，估算步行消耗。`
- 如有接口关联选项，对应 wx.getWeRunData / wx.authorize 的 scope.werun；保留现有头像、昵称、照片等真实使用项目。
- 如要求补充使用场景：`用户主动连接微信运动并授权后，在打开小程序期间同步微信提供的近期每日步数，用于展示与步行消耗估算；拒绝授权不影响其他功能。`
- 如要求说明数据保存：`按账号保存每日步数及同步时间，用户删除个人数据时一并删除。` 当前按同步时的最近31个日期保留记录，但没有独立的闲置账号定时删除任务，不宣称超过31天自动删除。
- 根据后台流程保存并使该指引生效；修改本地隐私页面不能替代平台声明，不关闭隐私检查绕过限制。

已修正客户端：将该错误分类为 privacy_not_declared，提示需要开发者补充声明，停止后台自动重试；设置返回中缺少 scope.werun 代表尚未申请，不能提示“权限仍未开启”。管理员完成声明后，重新打开最新开发预览，手动连接触发新授权，再验证 CloudID 及云端步数同步。

2026-11-04 管理员已更新后台指引，并手动同意开发者工具中出现的新隐私提示。随后通过真实原生接口核验：scope.werun=true，wx.login 后 wx.getWeRunData 返回 CloudID。测试云函数 coach_test（e33fc02235f1a413）调用 activity.steps.sync 返回 code=0，保存31个日期的数据，包含今天且来源均为 wechat。再调用今日页现有 syncSteps 流程并返回今天，页面已显示步数及同步时间，connected=true、platformBlocked=false、无失败提示。未注入模拟授权或步数；这些结果来自开发者工具运行环境，手机端实际步数与微信运动一致性仍待真机验收。本次无需重新部署云函数。
