# 支付联调

## 分区与商品

开发版（develop）调用 coach_test；体验版（trial）和正式版（release）调用 coach_prod。服务端根据部署分区选择金额，不接受客户端传入的价格或分区覆盖。

| 套餐 | 测试商品价格 | 正式商品价格 | 对应云函数环境变量 |
| --- | --- | --- | --- |
| 月度指导 | ¥0.01（1 分） | ¥19（1900 分） | PAY_PRODUCT_MONTH |
| 年度指导 | ¥0.02（2 分） | ¥198（19800 分） | PAY_PRODUCT_YEAR |
| 三年指导 | ¥0.03（3 分） | ¥298（29800 分） | PAY_PRODUCT_THREE_YEAR |

在微信虚拟支付后台分别创建并发布六个不同商品。服务端 `payment-products.js` 已按分区内置这六个公开商品 ID；也可在 coach_test／coach_prod 中通过对应环境变量覆盖。显式配置空值会阻止开放会员购买。同一变量在两套函数中的值不同，不要混用商品 ID；商品实际售价必须与该分区的服务端金额一致。三年期限是否支持，以实际平台商品审核结果为准。

这里的 test 是业务数据分区，支付参数仍为 env=0。测试订单也会真实扣款，不是模拟支付。体验版走正式商品，不能用于一分钱测试。

订单保存自己的商品 ID、价格和期限，后续发货回调按该订单核验。变更价格或商品后不再复用不匹配的待付订单，旧订单继续保留，可查询状态。

2. 按《部署与验收》和《个性化指导改造》配置支付凭据、加密回调、内容与服务依赖。密钥只配置到服务端，不放前端或聊天中。商品 ID 可用于配置核对。

4. 使用明确目标部署本次生成的业务函数和需要同步的回调、任务函数，核对 sourceVersion。将业务函数超时调至 30 秒、回调 15 秒、任务 60 秒（原部署仍是 3 秒）。
5. 在开发版先验证三档价格、支付取消、支付成功后服务端确认、重复通知、订单恢复和退款。最终付款由用户在真机上完成。
6. 核对体验版、正式版展示 ¥19／¥198／¥298，签名中的 goodsPrice 与正式商品一致，再开放正式收款。

实际支付必须以服务器查单或可信回调确认为准。仅支付窗口成功回调不直接解锁会员。
