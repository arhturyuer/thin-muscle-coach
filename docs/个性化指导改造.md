# 薄肌个性化指导改造

## 产品与实现

首页以薄肌生活图和具体解释承接新用户；按草稿／已出方案／会员状态继续路径。五组评估覆盖适用性、身体基础、目标经验、训练条件和饮食条件。不同训练日、时间、经验、器械、目标、外食方式和饮食难点会改变实际安排；禁忌未核验时不推荐具体餐食。

方案页免费展示首周摘要、一天三餐结构、动作视频与指导示例。套餐为月 19 元、年 198 元、三年 298 元，默认月套餐，功能相同，均含每天 30 次成功 AI 回复。每周计划独立于会员期限，历史训练绑定不可变周计划 ID。有效期内续购顺延，期限按北京时间自然月计算，月末钳制。

付款后进入「我的计划」，展示有效期、周安排与「开始今天的安排」；恢复日进入饮食记录，训练日进入动作执行。成长页累计跨周记录并提供复评。确认调整不会改动当前周，下周生成时采用。记录不足保持目标；足够记录结合难度和疲劳，每个动作最多较基线减少或增加一组。足够的前后两组身体记录才更新估算体重基线，单次波动不改目标。

## 接口

沿用业务函数的 `{action, ...data}` 与 `{code, stage, sourceVersion, data}` 信封。

| action | 输入 | 输出 |
| --- | --- | --- |
| bootstrap | owner、cursor | state（含 membership、proposal）、config（含 catalog 与功能状态）、aiQuota |
| plan.preview | assessment（schemaVersion=2） | plan（数值营养受审核开关控制） |
| plan.get | 无 | entitlement、membership |
| plan.generate | requestId、可选 assessment | 本周 entitlement 与 state；当前周有效时复用 |
| plan.review | requestId、baseVersion、review | proposal（含原因、规则调整、可用趋势） |
| plan.confirm | requestId、baseVersion、proposalId | entitlement 与 state；当前周有效时安排到下周 |
| purchase.create | sku、assessment、code | order 与原生支付签名；价格与期限由服务器决定 |
| ai.quota | 无 | remaining、date |
| ai.ask | requestId、date、message | request、remaining、date |
| ai.result | requestId、date | request 或 null、remaining、date |
| ai.history | date、offset（默认 0） | 最多 10 条完整问答、nextOffset、date |

`sku`: `month` / `year` / `three_year`。`review`: `difficulty=easy|okay|hard`、`fatigue=low|okay|high`、`hunger=low|okay|high`。

请求 ID 在客户端重试时保持不变，AI 同时携带首次请求的北京时间日期；成功回复持久化后扣次数。供应商错误、不完整输出、规则不通过均不扣次。原子预占防止超过 30 次，一个账号同时只生成一条；租约 60 秒，供应商超时 25 秒，过期重试使用新令牌防止旧工作覆盖。客户端断网后可以查询已保存结果。达到次数上限不影响执行既有计划。

DeepSeek 使用官方 `https://api.deepseek.com/chat/completions`，默认 `deepseek-flash`，关闭思考模式，JSON 输出，最大 1,200 tokens，问题最大 1,000 字，最多携带当天最近 10 轮。AI 调整字段只允许 `reduce_load` / `keep` / null，不直接写计划；前端引导用户结合真实感受复评并确认。模型文本不能新增热量与克数处方，相关输出会被拒绝。

## 存储与长期容量

新增服务端专用集合：

- 测试：`coach_test_accounts_guidance`
- 正式：`coach_accounts_guidance`

集合客户端读写规则均须关闭，仅云函数访问。文档 ID 对账号与命名空间做 SHA-256，存储 `userId` 和 `key`。`plan:` 为不可变周计划快照；`ai:YYYY-MM-DD` 为每日额度与最多 30 条成功问答；`event:` 为幂等转化事件。

AI、历史计划与新增转化事件均不进入账号健康记录快照。同步先幂等归档有效事件再确认写入，避免页面访问事件耗尽原有账号记录容量。个人健康记录仍沿用现有容量保护。后续运营规模扩大时，应独立扩展健康记录分页归档，不直接删除历史记录。

删除个人数据会清除评估、身体记录、计划、复评、AI 对话和事件；只保留已脱敏交易元数据。账户删除标记使进行中的 AI 结果失效，清理失败可以重试。

## 上线配置与顺序

保持原支付凭据、内容视频、退款回调、分区配置；旧 `PAY_PRODUCT_ID` 保留用于核验未存商品 ID 的历史订单。新商品必须分别在微信后台创建并核验三年期限是否符合当前可售商品规则；平台能力或审核不通过时不可开放该套餐。

| 配置 | 用途 |
| --- | --- |
| PAY_PRODUCT_MONTH | 月度商品，后台 1,900 分 |
| PAY_PRODUCT_YEAR | 年度商品，后台 19,800 分 |
| PAY_PRODUCT_THREE_YEAR | 三年商品，后台 29,800 分 |
| DEEPSEEK_API_KEY | 仅云函数环境变量，禁止提交或写入小程序 |
| DEEPSEEK_MODEL | 可选，默认 deepseek-flash |
| AI_READY=true | 模型接入并验收完成后启用 |
| NUTRITION_REVIEW_ID | 营养规则专业审核记录标识 |
| NUTRITION_READY=true | 审核通过后启用数值营养 |
| MEMBERSHIP_READY=true | 新会员商品启用开关 |

`membershipEnabled` 同时要求会员开关、三个商品、AI 和营养数值审核就绪；实际下单另要求原支付与内容开关全部满足。单独打开会员开关不会收款。配置尚未完成时保留评估预览并说明服务准备中。

1. 完成以下营养规则审核与视频内容审核。配置 DeepSeek 并设置业务函数超时至少 60 秒。
2. 创建两个辅助集合，配置仅服务端读写；核验按 `userId` 查询与分页读取正常。
3. `npm run prepare:cloud`，先部署 test 业务及任务；共享回调兼容旧、新商品，通过测试订单验证后部署兼容回调。
4. 测试分区真机验证评估、支付、首次执行、复评、AI、到期与退款。真实付款由有权限的人员完成。
5. 部署 prod 业务和任务，再上传新版前端；配置未完成时维持销售关闭。完成验收才开启对应开关。
6. 回退时关闭 `MEMBERSHIP_READY` 停止新售，不回退到无法识别会员订单的旧服务端；维持新服务以交付已售权益。`AI_READY` 暂时关闭不会删除计划。

本次仅生成本地部署包，未把本地测试替身当作云端、DeepSeek 或真实支付验收结果。

## 待专业审核的营养规则表

规则版本 `guidance-1`；所有数值方案默认关闭，审核后才可启用。

| 项目 | 当前实现、待审核参数 |
| --- | --- |
| 自动方案适用性 | 成年 18–65 岁，BMI 18.5–30（不含 30），无适用性筛查限制；其余建议专业指导，不进入购买 |
| 基础代谢估算 | Mifflin–St Jeor：10×体重kg + 6.25×身高cm − 5×年龄 + 男5／女−161 |
| 日常活动系数 | 久坐 1.2、有走动 1.375、活动较多 1.55 |
| 目标修正 | 减脂为维持量×0.9、增肌×1.05、习惯×1.0；不低于估算基础代谢，四舍五入到 50 千卡 |
| 蛋白质 | 增肌 1.6g/kg，其余 1.2g/kg |
| 脂肪与碳水 | 脂肪约占能量 30%，碳水为剩余能量 |
| 三餐分配 | 30%／40%／30% |
| 复评边界 | 不足两次完整训练保持负荷；身体记录前后至少各三次才更新估算基线，不额外扩大能量缺口 |

这些是待审规则实现，不能将“已配置审核 ID”当作实际专业审核已经完成。公式来源：[Mifflin 等原始研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)。

## 指标与本地验证

转化事件：`home_viewed`、`assessment_started`、`assessment_step`（事件键带 step1–step5）、`assessment_completed`、`plan_viewed`、`sku_selected`（键含套餐）、`purchase_clicked`、`purchase_started`、`payment_cancelled`、`payment_failed`、`purchase_paid`、`first_task_started`、`review_submitted`。仅保存事件名、时间与日期，禁止放入身体数据或正文。

上线前保存旧路径可用时期的首次进入用户 cohort、付费人数及各步人数；新版按同口径比较，不将开关关闭期与可售期混算。主指标为首次进入用户的七日内支付成功率，辅助指标为评估完成率、预览到付款率、付款后一天内首次执行率和七日执行情况。按设备／购买能力分层时使用明确的技术分层信息，不采集身体属性作为分析事件。

运行 `npm test`、`npm run release:check`。新增测试覆盖真实服务入口与客户端的评估→月度支付确认→周计划→训练→同步流程（内存云替身），以及三档金额、自然月、重复回调、退款、历史周记录、规则差异、复评、30/31 次、并发、失败、跨零点和删除数据。

微信原生编译通过不等于视觉和真机验收；需在开发者工具与手机补充窄屏布局、固定购买栏、数字键盘、视频播放、隐私授权、iOS 购买限制和真实支付等验证。
