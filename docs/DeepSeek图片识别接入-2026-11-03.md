# DeepSeek 图片识别与成长计划接入

## 更正此前结论

此前将小程序成长计划赠送额度概括为“只能处理文字，不能用于照片识别”，结论有误。`deepseek-v4.1-flash` 同时支持图片输入，并属于新增可抵扣模型。官方明确无需手动开启，允许来源会自动使用赠送额度：

- [新增模型通知](https://docs.cloudbase.net/ai/ai-inspire-plan-new-models)
- [模型能力表](https://docs.cloudbase.net/ai/available-models)
- [官方云函数 SDK 接入](https://docs.cloudbase.net/ai/model/wx-server-sdk-access)
- [DeepSeek 图片输入格式](https://api-docs.deepseek.com/zh-cn/guides/vision/)

用户授权范围仍为现有额度。没有购买资源、升级套餐或打开付费视觉模型开关。

## 实现

- 默认视觉模型改为 `deepseek-v4.1-flash`，模型分组固定 `cloudbase`。
- 图片、食谱生成及教练问答默认通过 `wx-server-sdk` 原生 `cloud.ai().createModel('cloudbase').generateText()` 调用，保留云函数身份。直接 HTTP 通道只保留为显式配置的兼容方式，不在调用失败时自动切换。
- AI 业务函数使用官方文档要求的 `wx-server-sdk@3.0.5-beta.1`。非 AI 的定时任务和支付回调保留原依赖。
- 对成长计划覆盖的模型关闭深度思考并要求 JSON 输出；每次只进行一步生成，避免额外模型调用。
- SDK 单次调用使用 45 秒超时（图片接口明确指定），云函数运行时为 60 秒。结果仍经过营养结构、数值和用户权益校验。
- 图片成功诊断保存模型名、传输通道、Token 数及时间，不保存图片、提示词或密钥；失败诊断保留原有脱敏错误类型。

## 真实验证

测试环境：cloud1-d2glj4fu92e8f1497；函数：coach_test。

通过已登录的小程序运行时调用真实云函数，输入项目自带餐食示意图，没有使用用户私人照片，也没有新增实际摄入记录。真实模型返回 code=0、10 项食物及热量、克重、蛋白质、脂肪和碳水估算。诊断确认：

- model：deepseek-v4.1-flash
- transport：wx-server-sdk
- usage.total_tokens：899
- 首次验证源码版本：faf1e09f99e633bd

同一模型通过原直接 HTTP 通道仍被网关拒绝；原生 SDK 通道成功，不能将“只改模型名”视为完整修复。

控制台赠送资源包用量当时仍显示 0，属于尚未核实入账的展示，不能声称已从该计数中确认扣除 899。实际模型返回的 899 是本次请求 Token 用量；该模型与调用来源符合官方赠送额度范围。环境没有可用付费资源点包，本次没有更改计费或购买资源。
