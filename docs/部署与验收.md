# 薄肌教练 · 部署与验收

## 中文正式版与本地运行

用微信开发者工具导入仓库，首页为 `pages/today/index`。正式应用仅展示中文产品文案，使用微信原生导航、表单、选择器、开关、进度、视频、客服、订阅与隐私授权交互。

已彻底移除小程序中的模拟支付服务与入口。测试替身只在 `tests/fixtures/`，不属于小程序根目录，也不会进入上传包。没有真实云环境和资格配置时，只可浏览页面与填写本地草稿，不能付款或激活实际训练。

云环境已配置为 `cloud1-d2glj4fu92e8f1497`。按用户确认的个人主体版本，不额外展示运营信息栏；隐私与售后咨询保留原生微信客服入口。微信后台隐私保护指引仍需按实际数据使用配置。

执行 `npm run release:check`。缺少云环境配置、原生导航图标或残留开发入口时检查失败。该检查通过仍不能代替云端和真机验收。

训练与筛查内容必须经过专业审阅，动作视频须有授权。正式服务默认保持关闭，素材和审阅不齐全时禁止开放真实购买。

## 云端准备

1. 在小程序后台确认实际服务类目、个人主体虚拟支付资格和商品审批；不能为了支付能力把业务虚构为其他类目。若账号不支持匹配产品的支付路径，暂停真实收款发布并记录平台的具体反馈。
2. 使用同一个云环境 `cloud1-d2glj4fu92e8f1497`；开发版连接 test，体验版与正式版连接 prod。具体分区规则见 [测试与正式隔离](测试与正式隔离.md)。
3. 保留正式 `coach_accounts`、`coach_order_index`，新增 `coach_test_accounts`、`coach_test_order_index`。四个集合客户端权限均为 `read: false, write: false`，业务只经服务端 SDK 访问。
4. 建议为 `coach_accounts` 的 `_id` 排序保留默认索引；账号文档使用 SHA-256(openid) 作为 ID，订单索引用业务订单号。禁止为调试开放集合公共写权限。
5. 执行 `npm run prepare:cloud`，生成 `coach_test`、`coach_prod`、`reminderJob_test`、`reminderJob_prod`、`paymentCallback` 五个入口。使用显式目标脚本部署，或在工具中仅选择对应目标上传并安装依赖，不引用包外目录。
6. 配置环境变量（下面列出）。不要把密钥放在小程序代码、仓库或前端控制台。
7. 配置 `paymentCallback` HTTP 访问入口，选择 JSON 加密消息推送。平台填写对应 URL、Token、EncodingAESKey；订阅发货、退款和投诉事件。入口只接受加密消息，校验时间戳、签名、填充及 AppID。
8. 停用旧 `reminderJob` 触发器，按需部署两个分区各自的 5 分钟定时触发器。普通小程序调用会被拒绝；这个任务也对未完成订单主动查单。按实际用户量配置执行超时与告警，首版为小规模内测实现。

### 环境变量

| 参数 | 用途 |
|---|---|
| `APP_ID`、`APP_SECRET` | 本小程序服务端身份与微信接口访问 |
| `PAYMENT_READY` | `true` 才尝试开放真实支付；其他必需参数缺失时仍关闭 |
| `PAY_OFFER_ID`、`PAY_APP_KEY`、`PAY_PRODUCT_ID` | 已发布的直购商品，后台价格必须为 990 分；代码环境固定为正式支付 env=0 |
| `IOS_PAYMENT_READY` | iOS IAP 实际开通并联调后才能设为 `true` |
| `ENTITLEMENT_SECRET` | 随机高强度权益签名密钥，仅服务端保存 |
| `MESSAGE_TOKEN`、`MESSAGE_AES_KEY` | 支付 HTTP 推送的 Token 与 43 字符 EncodingAESKey |
| `CONTENT_PUBLISHED` | 正式内容审阅通过后设置为 `true` |
| `CONTENT_REVIEW_ID`、`MEDIA_LICENSE_ID` | 实际内容审阅及素材授权记录编号；审阅记录须另行存档 |
| `EXERCISE_MEDIA` | JSON：`squat`、`push`、`bridge`、`bird`、`row` 对应的授权演示视频 `cloud://` 文件 ID；五项完整才开放正式内容 |
| `REMINDER_TEMPLATE_ID` | 当前账号审核通过的订阅模板 ID |
| `REMINDER_FIELD_MAP` | JSON，例如 `{"title":"thing1","description":"thing2"}`，必须替换为实际模板语义匹配的字段；当前适配器要求两个文本字段 |
| `MESSAGE_STATE` | test 固定 developer；prod 默认 formal，首发前可覆盖为 trial |

先确认提供的模板字段符合实际业务与长度限制。如果账号没有适合上述字段的模板，调整 `server/platform.js` 的数据映射并重新准备部署包，不发送语义不匹配的模板消息。

参考：[腾讯云开发虚拟支付接入参考](https://github.com/TencentCloudBase/skills/blob/main/skills/cloudbase-wechat-integration/references/virtual-payment.md)、[微信虚拟支付接口](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)、[订阅消息说明](https://cloud.tencent.cn/document/product/1301/103770)。以实际后台权限及官方当前协议为准。

## 业务约束

- 本地状态即时呈现；页面不直接调用云数据库。首次启动或前台恢复超过 5 分钟统一 bootstrap；按游标返回变化记录，订单、权益与配置一起更新。
- 修改 30 秒后合并同步；训练完成立即尝试。失败留在队列，恢复联网、再次启动或手动同步时重试。后台执行不作可靠性保证。
- 服务器逐项校验归属、数据、付费计划和版本；操作 ID 去重。冲突保存本机草稿，由用户选择保留本机或云端；无效记录也保留草稿并展示原因。
- 支付成功回调不直接发权益；可信发货通知或主动查单确认后才解锁。订单金额由云端固定，客户端身份不作为付款证明。
- 首训联网激活，上海时区当天为第 1 天。到第 8 天零时停止创建训练。历史离线记录仍可补同步；退款后拒绝对应训练写入。
- 权益凭证用于缓存标识，客户端不包含签名密钥。云端从不相信客户端付费标记；离线终端不能即时得知退款，重新联网时撤销缓存权益。
- 每天最多一条合并消息；超过提醒时间一小时不补发。发送前事务占位，超时不自动重试，采用至多一次策略避免重复；因此极端情况下可能漏发。授权耗尽后暂停发送，用户再次自愿授权后恢复。客户端返回 accept 不被当作长期推送许可，最终由微信发送接口裁决。
- 数据删除清理健康内容、本机缓存与提醒，并撤销本轮权益。必要交易元数据和订单归属索引保留用于对账及售后；订单内的计划和评估被删除。运营者需在上线前确定并公示交易保留期限与后续清理流程。
- 首版按账号事务保存业务快照，适合小规模内测。达到 700 KB/账号、3000 条记录或 10000 个操作 ID 时拒绝继续增量写入并提示客服，不静默丢数据；扩量前需迁移到分集合存储及可归档操作账本。

## 原生交互与自动化验证

`npm test` 覆盖领域计算、服务端边界、加密支付通知、账户隔离、并发同步、分区隔离及付款确认完整闭环。`npm run check` 检查 JavaScript、JSON、页面路由与共享代码一致性。微信工具的 wcc、wcsc 可独立编译 WXML/WXSS。

自动化测试不能代替云端 SDK、真实订阅模板与真机付款验证。

## 发布与回退

在同一云环境中先部署 test 并用开发版验证，再部署同一源码版本的 prod 并用体验版验收后发布。记录应用版本、云函数版本、共享领域版本和内容审阅编号。异常时设置 `PAYMENT_READY=false` 停止新购买；关闭定时触发器暂停推送。恢复既有稳定函数与小程序版本，保留既有订单和记录，不通过清空数据库回退。

尚需实际账号后台操作才能完成的事项：支付资格与商品审核、云端部署、密钥、订阅模板、内容审阅、授权视频、客服和隐私配置，以及真机支付/退款/通知验收。当前仓库未对真实用户收款或推送。

## 正式版交互回归补充

- 中文品牌、标题、日期、单位与服务状态，首页和成长页无英文占位文字。
- 原生底部导航有正常/选中图标，原生 navigator 保留微信返回栈。
- 表单点击提交时能取得键盘尚未失焦的内容；输入控件具备数字键盘、长度限制和原生提交。
- 拒绝隐私授权时不上传评估；拒绝订阅时开关恢复；修改提醒时间不重复请求订阅。
- 长错误使用微信原生弹窗，短提示使用轻提示，取消操作不报错，界面不显示代码路径或云端异常堆栈。
- 训练退出提示说明进度已保存；结束训练操作面板区分暂停、保存和不适。
- 今日、成长、订单与我的支持原生下拉刷新；新版本就绪后由用户选择立即更新或稍后再说。

尚未完成开发者工具的可视化真机/模拟器点击验收。编译检查与自动化组件行为测试通过不代表上述真机项目已经完成。
